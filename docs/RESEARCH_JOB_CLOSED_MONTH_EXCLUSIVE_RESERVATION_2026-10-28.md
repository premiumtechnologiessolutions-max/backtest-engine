# Quant Research Terminal — POSIX exclusive closed-month reservation (2026-10-28)

This is **execution infrastructure only**, not a backtest worker. `scripts/research_job_month_lease.py` provides `reserve_closed_month(root, fingerprint, month, now_utc=...)`, a local context manager that refuses to reserve a month until its UTC calendar period has ended. It calls `verify_plan` (which rechecks frozen queue metadata, exact clean Git HEAD and deterministic plan snapshot) **both before and after** acquiring an exclusive, nonblocking POSIX `flock`. Competing reservations for the **same frozen request and month** fail; different months may be reserved concurrently. A crashed process releases its kernel lock automatically; empty lock files may remain for safe reuse.

Owner-only `reports/research_job_locks/` and 0600 empty regular lock files are required. Symlinked directories, linked/nonregular files, nonempty locks and permissive permissions fail closed. No subprocess, quotes, external network, orders, broker connectivity, checkpoint, P/L, drawdown or source-coverage attestation is created. A reservation is **not** a durable queue state or an actual run. This only prevents accidental duplicate local worker reservation on a trusted POSIX filesystem; distributed/multi-host filesystems, Windows ACLs, adversarial same-user processes and NFS locking are not certified. Do not use it for live trading.

To use in a future offline worker, first verify private SHA-256 data and source calendar coverage, require an explicit operator-approved frozen execution manifest, then acquire the month reservation while running the canonical engine with bounded resources. Persist independent source-verified month ledgers and durable checkpoints under a separate strict schema; never infer performance from a reservation. Apply embargo and multiple-testing corrections before any prospective claims. Keep PR #1 Draft; research totals and approved-strategy count remain unchanged.
