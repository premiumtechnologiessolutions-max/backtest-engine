# No Risk FX — Audited Candidate Screen (2026-10-29)

This is an implemented **read-only selection stage** for the existing offline frozen
batch research pipeline. Code: `scripts/research_candidate_screen.py`.
Regression tests: `tests/test_research_candidate_screen.py`.

## Scope

1. Accept a *frozen* `NRFX_FROZEN_BATCH_V1` research plan and an existing
   `batch_manifest.json` generated by `scripts/research_batch_orchestrator.py`.
2. Re-check the private source archive SHA256 and clean checkout's exact pinned
   Git revision, without copying or exporting raw BID/ASK data.
3. Hold the batch's exclusive lock and re-run the canonical `audit_run` for
   **each accepted** experiment, including the 0.40 USD/oz all-in fee and
   monthly/weekly/individual ledger reconciliation.
4. Require complete, common **training** and **later review** month windows.
   Experiments with missing comparison months are explicitly marked
   non-comparable; a batch failure, mismatched manifest, tampered evidence or
   no comparable candidates aborts publication. **Any unexecuted or
   non-comparable job makes the entire search universe incomplete: all
   exploratory eligibility labels and ranks are suppressed**, even for jobs
   with attractive training results. Descriptive metrics remain visible.
5. Rank candidates by **training evidence only**:
   preliminary eligibility = at least 20 training trades, at least 60%
   strictly profitable training months, and positive training net USD/oz;
   ranking = eligibility first, then positive training month fraction,
   training net, monthly closing-equity drawdown, stable job ID.
   Thresholds are explicit research-screen heuristics, **not** statistical
   significance or an alpha test.
6. Record later-review metrics **only after** training-based ranking. Changes
   to later-review results cannot change eligibility or rank.
7. Write `candidate_screen.json` atomically and
   `candidate_screen.html` as a local, owner-private HTML report. No API,
   hosting, broker access, live trades, raw quote export, or PR merge.

## Usage on an existing audited local batch

Run from the repository root on POSIX, with the original private source
archive available in its frozen plan and `HEAD` matching that plan's
`engine_commit`:

```bash
python -m scripts.research_candidate_screen \
  --plan /private/research/plan.json \
  --batch-output /private/research/output \
  --train-start 2012-01 --train-end 2016-12 \
  --review-start 2017-01 --review-end 2018-12 \
  --min-train-trades 20 --min-positive-fraction 0.60
```

These dates are illustrative; every compared job must contain both complete
windows. **2017–2018 are not claimed independent OOS**, because these periods
may already have been researched or exposed in earlier sessions.

## Scientific warnings and next release gates

- This report is **HISTORICAL_EXPOSED_NOT_OOS_NOT_LIVE_APPROVED**.
- The review period is descriptive, not automatically independent.
  Even a training-only ranking can be subject to selection bias and multiple
  testing across thousands of search candidates. No false-discovery-rate,
  family-wise-error, or Deflated Sharpe correction is implemented here.
- The drawdown metric is based on *month-end closed P/L* and does **not**
  bound intramonth unrealized drawdown, leverage/margin exposure, slippage,
  quote-gap uncertainty, or true broker tick fills.
- It is not a guarantee that any month is profitable; ranking a batch with
  many negative candidates is not proof a tradable strategy exists.
- Before promotion to independently validated research:
  complete authorized original Gold ZIP SHA-pinned 13-field replay,
  finish real canonical multi-year runs, preregister truly untouched
  validation periods and selection policy, implement multiple-comparison
  safeguards, and run full repo CI on the final commit.

No raw Gold archive is contained in this change. PR #1 stays Draft.

## Incomplete-universe fail-closed correction — 2026-10-29

An earlier single-window screen could display `PASSED_EXPLORATORY` and rank 1
for an attractive finished job even while other frozen jobs were unexecuted or
non-comparable. This invites selection bias: unseen candidates can change the
research family and invalidate any ranking. The screen now returns
`INCOMPLETE_SEARCH_UNIVERSE`, lists unexecuted/non-comparable job IDs,
sets every candidate's `training_rank` to null, and labels all descriptive
rows `NOT_ELIGIBLE_BATCH_INCOMPLETE`. Only a complete audited universe
receives training-only ranks. This is a **scientific governance gate**, not
an adjusted p-value, forward validation or profitability proof.

Three synthetic regressions were added for partial manifests, missing review
months and a complete-universe control. The full current-HEAD repository suite
and GitHub Actions result must be verified separately. No private Gold data
was uploaded, and PR #1 remains Draft/unmerged.
