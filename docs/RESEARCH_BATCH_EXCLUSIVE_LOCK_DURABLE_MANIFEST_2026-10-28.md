# Research batch execution serialization and durable evidence — 2026-10-28

This change hardens the **existing executable offline frozen batch orchestrator**, not the prospective monthly Research Jobs worker. It introduces an exclusive POSIX `flock` held throughout canonical subprocess execution, report reconciliation, manifest writes, and index generation for the same output directory. Concurrent invocations targeting the same output now fail closed instead of racing to launch duplicate experiments or overwrite a shared manifest. The lock file persists and must never be deleted while an execution might be active.

`atomic_manifest` now uses an unpredictable owner-only temporary file, file fsync, atomic replacement, and parent-directory fsync. Symlinked or hardlinked manifest targets are rejected; a failed replace preserves the prior version. Symlinked output roots are rejected before resolution. Synthetic regression tests cover contention, exception release, unsafe lock inodes, swapped paths, atomic replacement failure, private permissions, and lock retention through a mocked canonical execution.

**Limitations:** This is cooperative per-output serialization on POSIX, not an untrusted multi-user sandbox, distributed queue, broker execution, or a proof against a same-owner adversary removing the lock path during a long run. The older batch runner still requires a frozen historical plan and a locally present exact-SHA private archive; the newer prospective Research Jobs queue is still metadata-only.
