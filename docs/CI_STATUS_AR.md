## الدليل المباشر
- تشغيل PR رقم 14: https://github.com/premiumtechnologiessolutions-max/backtest-engine/actions/runs/40207431735
- الحالة `failure` بعد نحو ثانيتين.
- `runner_name` فارغ، و`steps: []`، أي لم تظهر أي خطوة تنفيذية (لا install ولا pytest).
- تنزيل سجلات الوظيفة عبر GitHub API أعاد `BlobNotFound` / HTTP 404.
- تكرر النمط بعد إزالة pip cache من workflow؛ إذن لا يوجد دليل على أن خطأ Python هو سبب الفشل.

**الاستنتاج المحدود:** الفشل يحدث قبل خطوات الاختبار، لكن السبب الجذري غير مؤكد. يمكن أن يكون إعداد GitHub Actions/runner أو حساب/فواتير أو قيود مستودع. لا يصح الجزم بأي منها دون رسالة GitHub الظاهرة في واجهة التشغيل.

## قائمة التشخيص السابقة قبل التحقق المحلي الكامل
1. افتح صفحة التشغيل أعلاه وافحص التحذير الظاهر أعلى الصفحة، خصوصاً Runner / Billing / Actions permissions.
2. راجع Settings → Actions → General وتأكد من السماح بتشغيل workflows على المستودع الخاص.
3. راجع Usage/Billing وحدود GitHub Actions إن كانت الواجهة تعرض حظراً أو رصيداً غير متاح.
4. بعد حل المشكلة أعد التشغيل، ثم لا تدمج PR #1 إلا بعد نجاح `pytest` و`norisk --help`.
5. يمكن مؤقتاً إجراء اختبارات محلية بعد تثبيت `pip install -e ".[dev]"` في بيئة Python 3.11+.
